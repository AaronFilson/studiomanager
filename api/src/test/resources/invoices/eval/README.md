# Invoice eval cases

Each folder is one document. `InvoiceEvalTests` scores the recorded answers in CI per split (`dev`
and `test`); `LiveInvoiceEval` and `LiveDocumentServiceEval` read the files live and record the
answers (docs/planning/16, "Evaluation"; docs/planning/24).

| File | What it is |
|---|---|
| `expected.json` | The right answer, in `ClaudeInvoiceAnswer`'s v2 shape (v1 answers stay compatible) |
| `case.json` | Case metadata: `source`, `license`, `tags`, and `split` (`dev` or `test`) |
| `invoice.jpg`, `.png` or `.pdf` | The document |
| `claude.json`, `azure.json`, `google.json` | Recorded answers. Check before committing that none holds a customer's name, address, phone or email |

Only documents that may be public go here: synthetic ones (generated by `e2e/scripts/generate-eval-invoices.mjs`),
and public ones whose license allows it (`sources.json`, fetched via `bash scripts/eval-sources.sh`).
Real invoices belong to the people who received them. The owner's own live in `../private/`, which
git ignores as a whole: files, answers and notes. They're read by the live eval on the owner's
machine and never reach GitHub or CI. Confirmed studio invoices can be exported straight into that
format via `GET /api/v1/studios/{studioId}/invoices/{invoiceId}/eval-export`.

## How `expected.json` is written

- Values are what the document itself prints. `""` where it prints nothing.
- **No derived values.** A handwritten form whose Amount column holds the line total gets
  `lineTotal` and no `unitPrice`. Nothing is computed or corrected.
- **Crossed-out rows aren't lines;** record their text in `crossedOut`.
- **Shipping, handling, fees, deposits and discounts printed as rows among the items stay lines**
  with their `kind` set (`SHIPPING`, `FEE`, `DISCOUNT`, `DEPOSIT`). `shipping` is filled only when
  printed outside the item rows, next to the subtotal and total.
- **Other papers in the photo aren't the invoice.** Describe them briefly in `otherPapers` and copy
  payments shown on receipts or card slips into `payments` (never card digits).
- **A value hidden in the photo is `""`.** It's scored on what can be seen.
- **A date with no year printed** gets the true year in `invoiceDate`, the written text in
  `invoiceDatePrinted`, and `invoiceDateYear` set to `FROM_PAGE` or `ASSUMED`.
- **When "Retail" and "Your Price" are both printed,** the unit price is the one charged.
- **Packing lists** set `documentType` to `PACKING_LIST` and leave money fields empty.
